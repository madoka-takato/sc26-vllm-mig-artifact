# A1/README.md

## A1: Single-Server Characterization

### Purpose

This artifact reproduces the single-server performance experiments presented
in Figs. 1 and 2 of the paper. The experiments evaluate both software-based
GPU sharing (*vLLM-only*) and MIG-based GPU partitioning.

### Contents

* `docker_run_vllm_only.sh` – launches a vLLM server without MIG.
* `docker_run_mig.sh` – launches a vLLM server on a specified MIG device.
* `benchmark.sh` – executes `vllm bench serve` for performance evaluation.
* `plot_fig1_throughput.py` — plots the throughput comparison for Fig. 1.
* `plot_fig2_throughput.py` — plots the throughput of different MIG profiles for Fig. 2.
* `example_outputs/` – example benchmark results generated by `vllm bench serve`.

### Prerequisites

* Docker Engine
* NVIDIA Container Toolkit
* NVIDIA H100 GPU
* NVIDIA Driver 535.288.01
* CUDA 12.2
* Container image: `vllm/vllm-openai:v0.19.0`

## Reproducing Fig. 1

1. Launch the vLLM-only server with `gpu-memory-utilization=0.1`.
2. Run `benchmark.sh`.
3. Repeat the experiment with `gpu-memory-utilization=0.9`.
4. Enable MIG and create a `7g.80gb` GPU Instance.
5. Launch the vLLM server on the created MIG device with
   `gpu-memory-utilization=0.1`.
6. Run `benchmark.sh`.
7. Repeat the experiment with `gpu-memory-utilization=0.9`.

## Reproducing Fig. 2

1. Create one of the following MIG profiles:

   * `1g.10gb`
   * `1g.20gb`
   * `2g.20gb`
   * `3g.40gb`
   * `4g.40gb`
   * `7g.80gb`

2. Launch the vLLM server on the selected MIG device.
3. Execute `benchmark.sh`.
4. Repeat each measurement three times.
5. Plot the Output Token Throughput values for each individual run.

## Expected Output

`vllm bench serve` reports the Output Token Throughput for each run.
The throughput values are summarized in an Excel file and plotted using the
provided `plot_throughput_fig1.py` and `plot_throughput_fig2.py` scripts to reproduce Figs. 1 and 2.
Example benchmark outputs are included with the artifact.
